# PPT → MSP: инструкция по тесту, выводы и внедрение

Документ для самостоятельной проверки демо и передачи команде/заказчику (XCA).

Связанные файлы:
- UI: [`demo_app.py`](demo_app.py)
- Краткая шпаргалка запуска: [`README_DEMO.md`](README_DEMO.md)
- Код пайплайна: папка [`demo/`](demo/)

---

## 1. Что это

Веб-демо (Streamlit): подрядчик присылает **PPT (stroyka)** → система считает сроки по **Режиму №1** → выдаёт обновлённый **CSV/XML** для MS Project (+ опционально MPP только на Windows с Project).

Формулировка КП: *«веб-ввод данных → расчёт сроков начала/окончания в MS Project по фактическим данным → отображение»*.

| Контур | Смысл | Статус после теста |
|--------|--------|-------------------|
| **A — BI-дашборд** | Сроки/отклонения в вебе (и далее в BI) | Возможен; прототип = это демо |
| **B — импорт в Project** | CSV/XML → File → Open | **Подтверждён** (XML) |
| Прямой `.mpp` | Без MS Project / библиотек | **Не делаем**; только XML/CSV (+ COM локально) |

## 3. Самостоятельный тест (чеклист)

### 3.1. Демо-файлы (то, что присылал заказчик)

1. Сайдбар → **«Демо-файлы Ленинский»**.
2. Дата «сегодня» = **25.07.2026** (для воспроизводимости цифр теста).
3. **«Рассчитать и подготовить файлы»**.
4. Ожидание в диффе:

| Id | Работа | Начало стало | Окончание стало | Осталось дн |
|----|--------|--------------|-----------------|-------------|
| 6 | Фундаменты сборные | 13.04.26 | 01.10.26 | 68 |
| 8 | Монолитная плита… | 29.06.26 | 22.08.26 | 28 |

5. Скачать **`msp_updated.xml`** (предпочтительно) и/или CSV / ZIP.

### 3.2. Импорт в MS Project (ключ для варианта B)

1. MS Project → **Файл → Открыть** → `msp_updated.xml` → режим **«Создать новый проект»** → Готово.
2. Сохранить как `.mpp` (например `test_import.mpp`).
3. Добавить колонки **Предшественники** / **Последователи**.
4. Проверить:

| Проверка | Ожидание | Результат теста 25.07.2026 |
|----------|----------|----------------------------|
| Id6 даты | 13.04.26 / 01.10.26 | OK |
| Связи Id6 | последователи `8ОН+13`, `10ОН+143`… | OK, не слетели |
| Связи Id8 | предшественник `6ОН+13` | OK |
| Каскад | окончание Id6 = 01.10.26 → начало плиты ≈ **21.10.26** (= +13 раб.дн) | OK |

5. Если мастер планирования пишет «дата раньше начала проекта» — **Продолжить**.
6. `?` у длительности = флаг «оценка» в Project, **не ошибка**.

### 3.3. Загрузка «своих» новых файлов

1. Сайдбар → **«Загрузить свои файлы»**.
2. Обязательно: `.pptx` (stroyka) + `.csv` (экспорт из Project, cp1251, `;`).
3. Опционально: `.xml` (появится `msp_patched.xml`), `.mpp` (только локально с Project).
4. Рассчитать → скачать CSV/XML/ZIP → снова открыть в Project.

### 3.4. CSV vs XML

| Формат | Когда |
|--------|--------|
| **XML** | Канонический round-trip в Project (подтверждён тестом) |
| **CSV** | Запасной обмен; карта полей при импорте важна |
| **MPP** | Только машина с Project (COM); на Streamlit Cloud **нет** |

## 4. Размещение как Streamlit-приложение (Cloud)

Кратко: нужен **GitHub-репозиторий** + деплой на [share.streamlit.io](https://share.streamlit.io) (как showcase).

Подробные шаги — в интерактивном прогоне с разработчиком; чеклист:

1. Создать репозиторий (например `ppt-msp-demo` или `bi-analytics-msp-demo`).
2. В корне репо должны быть:
   - `demo_app.py`
   - `demo/` (пакет)
   - `sample_data/` (pptx + csv; `.mpp` лучше не класть на Cloud — тяжёлый и бесполезен без Project)
   - `requirements.txt` (для Cloud; см. ниже)
   - этот документ / README
3. Push в GitHub.
4. Streamlit Cloud → **New app** → указать репо → Main file: `demo_app.py` → Deploy.
5. URL вида `https://….streamlit.app` отдать заказчику.

**Ограничения Cloud:** нет Microsoft Project → нет кнопки MPP; только расчёт + скачивание CSV/XML. Вариант B заказчик проверяет у себя в Project на Windows.

Файл зависимостей для Cloud — `requirements.txt` (копия без pywin32):

```

```

## 5. Выводы теста (25.07.2026)

1. **Парсинг PPT** через встроенный Excel (OLE) работает на тестовых слайдах (фундаменты + монолитная плита).
2. **Режим №1** даёт воспроизводимые даты при фиксированной «сегодня».
3. **Сопоставление** PPT↔задачи MSP по названию/объёму — OK на 2 работах.
4. **Импорт XML в Project** — файл открывается, структура задач на месте.
5. **Связи сохраняются**; при автоматическом планировании **каскад пересчитывается** (подтверждено: плита стартует через 13 раб. дней после окончания фундаментов).
6. После «голого» импорта даты могут сначала отличаться от демо, пока не зафиксированы ограничения/пересчёт; после установки окончания Id6 = 01.10.26 каскад сходится с ожиданием.
7. Прямая запись `.mpp` без Project **не требуется** для архитектуры B.

Старые формулировки «решение A/B не принято» и «ключевой тест импорта не завершён» — **снять**: тест B завершён положительно; A возможен как дополнение.

## 6. Рекомендации: архитектура A + B

### Рекомендуемое решение

**Делать оба контура:**

```text
PPT (еженедельно)
    → сервис расчёта (Mode1 + маппинг)
         ├─→ CSV/XML → импорт в MS Project     [= B, для планировщика]
         └─→ БД / msp_*.csv → BI-дашборд       [= A, для руководства]
```

- **Project** — рабочий график и каскад зависимостей (движок MS Project).
- **BI** — сроки, отклонения, % ВОР, прогноз дней, статус по объектам.
- Обмен с Project — **XML** (основной), CSV — запасной.
- Бинарный MPP не генерировать на Linux/Cloud.

### Вариант «только A»

Возможен, если заказчик согласен, что «истина для отчётов» — BI, а Project обновляют вручную или реже. Минус: расхождение графиков без дисциплины обмена.

### Вариант «только B»

Возможен (уже доказан). Минус: нет единой веб-витрины для руководства без открытия Project.

## 7. Рекомендации по дальнейшей разработке

### Ближайший MVP (1–2 итерации)

1. Вынести расчёт в сервис/CLI без UI (тот же `demo/`).
2. Канонический выход: **XML** + лог `build_log.md` (было/стало).
3. Жёсткий справочник работ (Id + нормативное имя), не только fuzzy.
4. Явная политика **факт vs предшественник** (Actual Start / MSO), зафиксировать с Янчуркиным.
5. Убрать опечатки шаблона PPT (м4/м5, «борные», OLE «фахверк» vs слайд «плита») — правила нормализации.
6. Прогон на полном отчёте (10+ слайдов), не только 2 работы.

### Интеграция с основным BI (`bi-analytics`)

1. После расчёта писать снимок в формат `msp_*.csv` → существующий ETL `web/` → `web_data.db`.
2. Экран: сроки СМР, отклонение от базы, «осталось дней (прогноз)», фильтр по проекту UUID из имени stroyka.
3. Не читать PPT из дашборда напрямую — только результат расчёта из БД (как в `DASHBOARD_DATA_ARCHITECTURE`).

### Эксплуатация

1. Канал приёма PPT (почта / папка / кнопка в админке).
2. Версионирование: каждый прогон = timestamp + version_id.
3. Аудит: кто загрузил, какие Id изменились.
4. На Cloud — только демо без клиентских секретов; боевые данные — VPS/внутренний контур.

### Не делать

- Писать `.mpp` на Streamlit Cloud.
- Переписывать движок связей Project в Python «на всякий случай».
- Смешивать клиентский `web/` основного дашборда с демо-фикстурами.

## 8. Ответ для КП / протокола

> Архитектура выхода: **A + B**.  
> A — BI/веб по срокам и отклонениям (прототип: Streamlit PPT→MSP).  
> B — обратный импорт обновлённого **XML** (CSV — запасной) в MS Project: связи сохраняются, каскад пересчитывается (**тест 25.07.2026 — пройден**).  
> Напрямую с MPP без Microsoft Project не работаем.
